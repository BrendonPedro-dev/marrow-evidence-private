# Singapore - IP scale bands (independent rows)

Enrichment pass over `singapore/campaigns.md`. One row here per INDEPENDENT census row.
The census table is the index and is not edited by this pass.

**Band vocabulary (exactly these codes):** `lt_10k` / `10k_50k` / `50k_200k` / `200k_1m` / `gt_1m` / `unknown`.
These match the /start intake's `follower_band` codes character-for-character.

**Band definition:** the IP's PRIMARY channel following at the time of the campaign - **a single channel, not a cross-platform total**.
This distinction decides a band in this market: see rows 14 and 34.

**Evidence basis codes:** `at-campaign` (countable figure at or near the campaign window) / `current-proxy` (only a CURRENT count findable; retrieval date recorded, NOT at-campaign truth) / `unknown` (no countable public evidence; Notes record what was checked).

**Coverage:** 7 independent rows (1 REP=yes, 4 REP=unclear, 2 REP=no). 0 at-campaign, 7 current-proxy, 0 unknown.
**Singapore is the weakest market for at-campaign evidence found so far, and the reason is specific: none of the four Singapore outlets that carry these campaigns (eatbook.sg, thesmartlocal.com, geekculture.co) states a following for the IP it is covering.** Every band here is a proxy.

Note that this market's independent set is dominated by REP=unclear and REP=no. Only one row (3) is REP=yes, so Singapore contributes almost nothing to the priority tier.

## Method notes for this market

- **Same working curl channel as the Philippines**: a crawler user-agent (`Googlebot/2.1`, `bingbot`, or `facebookexternalhit/1.1`) against `https://www.instagram.com/<handle>/` returns an `og:description` with the follower count. A normal browser UA returns a login wall.
- **The `web_profile_info` API cooldown is long.** After it 401s (`"Please wait a few minutes before you try again."`) it stayed blocked across this market's work despite multi-minute gaps, so the unrounded counts that would settle row 33's boundary case could not be obtained. That is a *precision* limitation, not a coverage one - the boundary risk in row 33 is about the 2025 value, which no unrounded 2026 count could answer anyway.
- **X/Twitter is not curl-verifiable.** `https://x.com/<handle>` returns no `og:description` to any crawler UA tried, and `https://cdn.syndication.twimg.com/widgets/followbutton/info.json?screen_names=<h>` returns an empty 200. For X-primary IPs the only route is press stating the figure. This mattered for mofusand and was worked around because its Instagram is the larger channel anyway.
- **TikTok is not curl-verifiable** either - crawler UAs against `https://www.tiktok.com/@<handle>` returned nothing for all five handles tried.
- **Japanese PR TIMES releases are excellent dated evidence** and are fully curl-verifiable: the page carries a machine-readable `"datePublished"` and Japanese releases routinely quote an IP's SNS following in the headline. Worth using as a first stop for the Japan market's own rows.
- **Singapore's structural problem for this pass is that four of seven rows are company-owned plush/character brands rather than individual creators.** Their Instagram accounts are countable, but what is counted is a small brand's audience, not a creator's following. The bands are honest about what they measure; whether they are the same *kind* of quantity as an artist's following is a question the summary has to answer, not this file.
