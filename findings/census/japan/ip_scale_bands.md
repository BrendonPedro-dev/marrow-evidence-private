# Japan - IP scale bands

Per-row follower-scale bands for every INDEPENDENT row in `findings/census/japan/campaigns.md`.
Band vocabulary is exactly `lt_10k` / `10k_50k` / `50k_200k` / `200k_1m` / `gt_1m` / `unknown`, matching the /start intake's `follower_band` codes character-for-character.
Band reads the IP's PRIMARY single channel at campaign time - never a cross-platform total.

`campaigns.md` is not modified by this file.

**Scope:** 51 INDEPENDENT rows (26 REP=yes, 16 REP=unclear, 9 REP=no). No PORTFOLIO or UNCLEAR rows appear here.
**Retrieval date for every current count below: 2026-07-30.**

**Japan is the first market in this pass where X/Twitter follower counts could be verified at all.**
Every earlier market file states that X counts are not curl-verifiable, and that was true of the routes tried there (`x.com` serves no `og:description` to any crawler UA, and the twimg syndication endpoint returns an empty 200).
The working route is the fxtwitter API - `https://api.fxtwitter.com/<handle>` returns unrounded `followers` plus `name`, `description`, `tweets` and `joined` as JSON, with no rate limit encountered across roughly 90 calls in this session.
That matters more in Japan than anywhere else, because Japanese illustrator IPs are overwhelmingly X-native: **33 of the 45 banded rows here read from X**, and without this route most of them would have been `unknown`.
See the method section for the vxtwitter caveat and for what this implies as owed rework on the eight earlier files.

## Method and verification notes for this market

**X/Twitter counts are curl-verifiable after all, via fxtwitter - and this is the single most consequential method finding of the pass.**
```
curl -s "https://api.fxtwitter.com/<handle>"
```
returns JSON with unrounded `followers`, plus `name`, `description`, `tweets` and `joined`.
No rate limit was hit across roughly 90 calls.
`api.vxtwitter.com` exposes the same data as `followers_count` but returns `{"error": "Extract error"}` intermittently and unpredictably - it failed on `ui_shig`, `machikoriiita` and `kumamine`, all of which fxtwitter served correctly on the next call, so **fxtwitter is primary and vxtwitter is only a fallback**.
A handle with no account returns `{"code": 404 ...}` with no `user` object, so absence is cleanly distinguishable from failure.

**The `name` and `description` fields are what make this route safe, and they caught three errors that a count-only route would have shipped.**
`@rswxx` and `@lkpk_g` were assigned to the wrong creators on first read and the `name` field corrected them (row 52).
`@kurahashirei_ex` looked like the artist and is the exhibition's promotional account (row 132).
`@mofusand_mofu` - the most obvious mofusand handle - is a 0-follower account named とも created 2025-12-09.
Instagram's crawler-UA route serves **no biography**, only counts, which is precisely why row 80 is flagged as the file's weakest banded identification while row 84's identity could be confirmed (via the same creator's X bio).

**Owed rework on the eight earlier market files, flagged not done.**
Vietnam, Philippines, Singapore, Hong Kong, Thailand, Indonesia, Malaysia and Taiwan-v2 were all written on the recorded finding that X counts cannot be verified, and several of them name specific rows whose band was left uncertain for exactly that reason.
One of those is retired here: **Taiwan rows 18/53/68 band Kanahei off Instagram (215K) with a note that X is probably primary and unverifiable - X is 374,446, X is indeed primary, and the band does not change.**
The remaining X-exposed rows named in those files should be re-checked before the summary claims channel choices are settled.
The Facebook exposure (Taiwan's Capoo, LAIMO, 白爛貓, Mr. STRIKE; Malaysia's Shiba Says) is **not** addressed by this route and stays open.

**Campaign press yielded exactly one usable figure in 49 fetched sources, and one trap.**
All 51 census source URLs were fetched under a Googlebot UA (49 succeeded; row 20's wwdjapan returned 919 bytes and row 23's wego.jp returned 18) and grepped for フォロワー / フォロー数 / 万人 / followers / subscribers.
The one usable hit is row 141 (CyberAgent on 寺田てら, "Twitterのフォロワーは現在20万人を超える"), which **names the platform** - the Taiwan pattern rather than Malaysia's bare cross-platform total.
The trap is row 78, where the Kokuyo release states "SNS総フォロワー数250万人以上" - but that belongs to **おさき, a teenage model appearing in the campaign, not to the IP 一乗ひかる**, and it is a cross-platform total besides. Reading it as the IP's figure would have produced `gt_1m` against a true `10k_50k`, a four-tier error.
Every other フォロワー hit was PR TIMES's own "this company has N followers" widget (Loft 225, Calbee 185, Kokuyo 197, Bandai 65, and so on) - **noise that a naive grep will report as a hit in every PR TIMES-sourced row**, which is worth knowing for Korea.
Running rate across the pass is now roughly 4 usable hits in 217 sources.

**The census's own source pages are a much better handle vein in Japan than anywhere else in the pass.**
A single grep of the 49 fetched pages for `x.com/<handle>`, `instagram.com/<handle>` and `tiktok.com/@<handle>` recovered creator handles for 13 rows outright - collabo-cafe pages carry the creator's X handle inline as a matter of house style (rows 14, 63, 66, 132, 135, 136, 137), and brand-official pages carry entire rosters (row 52's three, row 140's four, row 79's two).
This inverts the finding from Thailand and Taiwan, where every social link in every census source resolved to a publisher, venue or brand.
Two handles were already recorded in `campaigns.md` itself (`@sakusya2honda` row 124, `@_kunika_` row 118) - worth grepping the census before searching.
Where the census pages were silent, the working order was: the IP's own website markup (`nishimura-yuji.com` gave row 23 after four failed guesses), then search, then name-guessing last.
**Name-guessing failed almost completely in Japan** - 28 candidate handles were tried across 19 IPs in one batch and 2 hit. Japanese illustrator handles are systematically unrelated to the creator's name (中村佑介 is `@kazekissa`, 遊ハち is `@nemone_2`, くらはしれい is `@hakoniwa01`, foxy is `@____foxy____`, イコモチ is `@rswxx`).

**The roster rule, new in this market.** Two rows are 12- and 18-creator rosters (77 and 19) where only 1 and 2 creators respectively could be evidenced.
The established convention - row band = highest band present, with per-creator bands in the detail table - was written for rows of two to five creators where most were evidenced (Philippines 74/75/81, Hong Kong 82, Indonesia 6/77, Malaysia 121, and rows 52 and 140 here).
Applying it at 1-of-12 would report a band that is an artefact of which creator happened to be findable.
