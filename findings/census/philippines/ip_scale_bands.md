# Philippines - IP scale bands (independent rows)

Enrichment pass over `philippines/campaigns.md`. One row here per INDEPENDENT census row.
The census table is the index and is not edited by this pass.

**Band vocabulary (exactly these codes):** `lt_10k` / `10k_50k` / `50k_200k` / `200k_1m` / `gt_1m` / `unknown`.
These match the /start intake's `follower_band` codes character-for-character.

**Band definition:** the IP's PRIMARY channel following at the time of the campaign.
Where a character has its own channel distinct from the creator's personal account, the character's channel governs.
Where the IP is an artwork with no channel of its own, the band reads from the creator's largest evidenced channel and the Notes say so.

**Evidence basis codes:** `at-campaign` (countable figure at or near the campaign window) / `current-proxy` (only a CURRENT count findable; retrieval date recorded, NOT at-campaign truth) / `unknown` (no countable public evidence; Notes record what was checked).

**Multi-creator convention.** Rows 74, 75 and 81 each carry several creators in one census row.
The main table keeps one row per census row and its Band cell holds the **highest band present in that row** - the strongest true statement of "this brand ran an IP at this scale".
The full per-creator bands live in the *Multi-creator detail* table below, and that table is the one to count from for creator-level distributions.

## Method notes for this market

- **The working curl channel for Instagram counts is a crawler user-agent against the plain profile URL.** `curl -A "Googlebot/2.1 (+http://www.google.com/bot.html)" https://www.instagram.com/<handle>/` returns an `og:description` meta tag reading "N Followers, N Following, N Posts - ...". A normal browser UA on the same URL returns a login wall with no count. Bingbot and `facebookexternalhit/1.1` work identically.
- **The `web_profile_info` API works but rate-limits hard and is not the tool to sweep with.** `https://www.instagram.com/api/v1/users/web_profile_info/?username=<h>` with header `X-IG-App-ID: 936619743392459` returns the *unrounded* `edge_followed_by.count`, which is worth one call when a value sits near a band boundary. After roughly 20 calls it returns HTTP 401 `{"message":"Please wait a few minutes..."}` for a long cooldown, and the cooldown is IP-wide across app IDs and hosts. Use `og:description` for the sweep, the API only for boundary cases.
- **`og:description` rounds to "15K" / "84K".** Every band call in this market survives the rounding, but a value that rounds to "10K" or "50K" straddles a band edge and must be re-read through the API.
- **Wayback does not help for Instagram.** Snapshots exist for these handles but the ones since roughly 2019 capture the login wall - the 2022 `robcham` snapshot has no follower count in it. This is why the PH rows are proxy-heavy: at-campaign banding here depends on press stating a figure, and Philippine campaign press essentially never does.
- **Behance is curl-verifiable** from the embedded `"stats":{"views":N,"appreciations":N,"followers":N,"following":N}` blob, and is the fallback when an artist has no usable Instagram (Al Estrella). It is systematically much smaller than Instagram for these creators, so it should not be used where Instagram exists.
- **StarNgage and other analytics mirrors return 403** and are not usable as evidence.
